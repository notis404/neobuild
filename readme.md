
neobuild is a stb style single-header library which simplifies the process of writing C programs that can compile C programs

The library was written for MSVC toolchains on Windows x64 platforms first because that is what I primarily use, but I plan to extend support for other compilers and OS platforms in the future. 

The MSVC compiler toolchain is particularly annoying to use since it requires the running process to have initialized all of the toolchain environment variables before it can be used (this is what calling vcvarsall.bat or using the Developer Command Prompt does). The initialization script for the MSVC toolchain is also painfully slow which makes adding it as a consistent step of the build process for each compilation undesirable. This library simplifies that process by programmatically locating any installed MSVC toolchains, calling the toolchain initialization script ONCE, and then saving those variables to a file on disk. Any subsequent runs just read from the environment variable file on disk directly which cuts the initialization time out of the process entirely while still allowing the compiler to run correctly with the Microsoft-supplied environment variables. 

MSVC toolchain installations are located using the Microsoft vswhere tool which is installed with any version of the compiler toolchain after VS2017: [vswhere](https://github.com/microsoft/vswhere)). Currently, the library uses the tool to just grab the most recent version of the compiler toolchain but in the future this should allow the selection of specific toolchain versions. It is possible for the library to support toolchains older than VS2017 as well but those installations need to be retrieved from registry keys which is not currently supported.

This library supports creating C programs that can compile C programs and thus, also recompile itself. The recompilation idea was borrowed from [nob.h](https://github.com/tsoding/nob.h) and refactored for Windows. If recompilation is set up in the build program's source file and the source file has been written to more recently than the build program executable, the library will recompile the executable in-place and run the newly-compiled version of the build program with the same arguments. 

Because of this ability to recompile itself, any neobuild executable configured to recompile can also be used to bootstrap a new build program. A simple bootstrap binary has been provided in the binaries folder, neobuild_bootstrap.exe. If you download a copy of that executable, move and rename the file where you would like the build tool to be, and call the executable with the arguments: -bootstrap \<new_build_source_file\>, the executable will recompile itself using new_build_source_file as the compilation target. Thus, there is no need to go and find vcvarsall.bat or use the Developer Command prompt to initialize and compile the initial build tool executable. The neobuild_bootstrap.exe stub provides all of that functionality. The source file for this bootstrap executable can be found in the src folder next to neobuild.h.
